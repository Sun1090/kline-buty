# 03 · 技术方案：架构、数据流与代理策略

> 技术栈（一期）：React 18 + TypeScript + Vite + lightweight-charts v5
> 移动端二期方案见 §6。

---

## 一、总体架构

```
┌─────────────────────────── Web 前端 ───────────────────────────┐
│  UI 层（React 组件）                                            │
│   交易对选择 │ 周期切换条 │ 指标面板 │ 图表面板 │ 深度/盘口(二期) │
│                              │                                  │
│  图表 Adapter（渲染层隔离层，唯一允许触碰 lightweight-charts）   │
│                              │                                  │
│  数据层（自建，不依赖渲染库）                                   │
│   BinanceClient: REST 历史分页 │ WS 客户端(重连/补数/订阅管理)   │
│   指标引擎: MA/EMA/BOLL/VOL/MACD/KDJ/RSI（纯函数，可单测）       │
└──────────────────────────────┬──────────────────────────────────┘
                               │ /api → 币安 REST     （Vite 代理或直连）
                               │ /ws  → 币安 WS        （Vite 代理或直连）
┌──────────────────────────────▼──────────────────────────────────┐
│ 币安公开 API（api.binance.com / data-api.binance.vision /        │
│ stream.binance.com）                                            │
└─────────────────────────────────────────────────────────────────┘
```

**核心原则：数据层与渲染层完全解耦。** 将来替换/自研渲染引擎时，数据层零改动。

## 三、关键数据流

### 3.1 历史加载（分页）

```
用户选择 BTCUSDT + 1m
  → REST /api/v3/klines?symbol=BTCUSDT&interval=1m&limit=1000
  → 转领域类型 Candle[]，写入 market 仓库缓存
  → 渲染左侧到当前时刻；滚动到左边缘时
  → 以最左 K 线 openTime 为 endTime 继续取下一页（去重合并）
```

### 3.2 实时更新

```
WS 订阅 btcusdt@kline_1m
  收到帧 k → market 仓库：
    若 t == 最新K线时间 → update 该根（跳动）
    若 t > 最新K线时间 → append 新根
  断线 → 指数退避重连（1s→2s→4s…上限30s）
  重连成功 → 以最新时间戳拉一次 REST 补齐缺口
```

### 3.3 指标联动

```
每次数据变更 → 指标引擎重算（增量：仅算新增/变更部分）→ 叠加在图上
副图（VOL/MACD/KDJ/RSI）与主图共享时间轴，上下联动
```

## 四、代理策略（关键：国内网络可达性）

| 环境 | 策略 |
|---|---|
| 本机开发（已实测可达） | 直连，Vite `server.proxy` 配置 `^/api → https://data-api.binance.vision`、`^/ws → wss://stream.binance.com`、`^/fapi`/`^/futures → https://fapi.binance.com`，统一走 `/api` `/ws` `/fapi` `/futures` 前缀，**前端不写死外部域名**，将来换环境零改动 |
| 部署到受限网络（大陆服务器/内网） | 启用自建代理层（Node/Express 或 Nginx）：`/api` 与 `/ws` 转发到币安，走 HTTPS + WS，可加缓存与限流 |
| 生产兜底 | 币安双域名（`api.binance.com` / `data-api.binance.vision`）主备切换 |

**前端规范：任何网络请求必须走相对路径 `/api` `/ws`，禁止硬编码外部域。** 这是代理方案成立的前提。

## 五、核心依赖

| 依赖 | 版本 | 用途 |
|---|---|---|
| lightweight-charts | ^5.x | 图表渲染（蜡烛/成交量/MA 线/十字光标） |
| react / react-dom | ^18 | UI |
| vite / @vitejs/plugin-react | ^6 | 构建 + dev 代理 |
| typescript | ^5 | 类型 |
| vitest | ^3 | 指标算法单测（可选） |

> lightweight-charts v5 注意：API 为 `createChart` + `chart.addSeries(CandlestickSeries, opts)`（v4 的 `addCandlestickSeries` 已移除）；时间戳须为秒级 UTCTimestamp。

## 六、移动端二期（预留方案）

- 优先 **WebView 套壳**（PWA/Capacitor）：复用一期全部代码，成本最低
- 需求升级后：**React Native + WebView 内嵌图表**，或自研原生 Canvas 渲染引擎
- 预留：数据层与指标引擎与平台无关，原生复刻时直接复用

## 七、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 币安 API 所在网络不可达 | 数据源中断 | 双域名 + 代理层 + OKX/Bybit 备选源（数据层已抽象，可插拔） |
| 币安 API 协议变更 | 数据解析失效 | 数据层单一封装点，适配层集中处理 |
| WS 断流丢 K 线 | 图表缺口 | 重连后 REST 补数（§3.2），仓库层幂等去重 |
| 大量 K 线内存/性能 | 卡顿 | 数据窗口裁剪（仅保留可视区 ± 缓冲），指标增量计算 |
| lightweight-charts 功能不足 | 被库约束 | adapter 隔离 + 备选 klinecharts（指标画线更全） |
