> 技术栈：React 19 + TypeScript 6 + Vite 8（rolldown）+ lightweight-charts v5

## 一、总体架构

```
┌─────────────────────────── Web 前端（React 19） ─────────────────────────┐
│  UI 层（展示组件，无渲染库依赖）                                         │
│   双端顶栏 │ 图表面板(ChartView/Pair/Quad) │ 行情列表 │ 盘口/深度/筹码    │
│   情绪 │ 仓位/快捷下单/流水 │ 价格提醒 │ 画线工具栏/图层 │ 设置/快捷键    │
│                              │                                            │
│  图表 Adapter（chart/adapter.ts，唯一触碰 lightweight-charts 的层）       │
│   （主图序列 + 指标叠加 + 画线 overlay + 盘口联动线 + 区域截图）          │
│                              │                                            │
│  业务逻辑（纯函数，可单测）                                               │
│   drawings/（40+ 画线几何与命中）│ trade/position/（模拟交易）            │
│   alerts/（提醒引擎）│ replay/（回放）│ indicators/（指标引擎）           │
│                              │                                            │
│  数据层（自建，不依赖渲染库）                                             │
│   data/binance/（REST 分页 + WS 看门狗退避重连）                          │
│   data/market.ts（领域仓库）│ data/cache.ts（本地缓存）                   │
└──────────────────────────────┬────────────────────────────────────────────┘
                               │ /api /ws /fapi /futures（Vite 代理或直连，
                               │   detectMode() 自动探测）
┌──────────────────────────────▼────────────────────────────────────────────┐
│ 币安公开 API（data-api.binance.vision / fapi.binance.com / dapi.binance.com│
│  / stream.binance.com，direct 模式带 CORS）                               │
└────────────────────────────────────────────────────────────────────────────┘
```

**核心原则：数据层 / 指标引擎 / 画线几何均为纯函数模块，与渲染层完全解耦。**
将来替换 / 自研渲染引擎时，数据层与业务逻辑零改动（移动端 WebView 套壳即复用同一套）。

## 三、关键数据流

> 本节按当前实现（2026-09）重写，与 `src/hooks/useKlineData.ts` / `src/data/` 对齐。

### 3.1 历史加载（分页 + 本地缓存）

```
用户选择 BTCUSDT + 1m
  → 先读本地缓存 readCachedCandles()（A13，6h TTL，校验失败自动失效静默降级）→ 秒开渲染
  → 同时 REST /api/v3/klines?symbol=BTCUSDT&interval=1m&limit=800 → 覆盖缓存并回写
  → 滚动到左边缘触发 loadMore：以最左 K 线 openTime 为 endTime，
    向前取 PAGE_SIZE=500 根（startTime/endTime 游标），去重合并，hasMore 幂等防重
  → ?perf=N（N>0）：进入合成数据压测模式（generateSyntheticCandles + tickSynthetic），
    不联网生成 N 根 + 模拟实时帧，供大数据量滚动/渲染验证
```

### 3.2 实时更新（WS + 看门狗 + 退避重连）

```
detectMode() 探测端点模式（proxy/direct，结果缓存）后建立 WS
WS 订阅 btcusdt@kline_1m
  收到帧 k → market 仓库：
    若 t == 最新K线时间 → update 该根（跳动）
    若 t > 最新K线时间 → append 新根
  每帧同时发布 live {price, dir} → StatsBar 涨绿跌红闪动（A5）
  消息看门狗（A14）：WATCHDOG_INTERVAL_MS=10s 内无消息判定断流
  断线/断流 → 指数退避重连：delay = min(30s, 1s × 2^min(attempt-1,5))（上限 30s）
  重连成功 → onReconnect 以最新时间戳拉一次 REST 补 100 根缺口（A3 简化版）
实时帧节流（A4）：同一 rAF 帧内多次 updateCandle 合并为一次重绘（scheduleDraw），末帧最新
```

### 3.3 指标联动

```
数据变更 → ChartView 窗口裁剪（cullWindow，可视区 ± 缓冲）
  → mainData/subData 按 windowData useMemo 重算（主图 MA/EMA/BOLL/SAR/Ichimoku/Supertrend，
    副图 VOL/MACD/KDJ/RSI/WR/OBV/ATR/DMI/CCI/PSY/STOCH/ROC/MOM/BBW/MFI/AO/CMF/Donchian/Aroon）
  → 叠加在图上；副图与主图共享时间轴，上下联动
  → 指标参数经 IndicatorSettings 即时生效（参数预设持久化 B15）
```

## 四、端点模式与网络策略（关键：国内网络可达性）

> 按当前实现（`src/data/binance/endpoints.ts`）重写：不再「前端一律走相对路径」，
> 而是**运行时动态探测** proxy / direct 两种模式。

### 端点模式探测（detectMode）

```
启动时 fetch('/api/v3/ping')：
  返回 JSON          → proxy 模式（走 Vite dev 代理 / 自建代理的相对路径）
  返回 HTML/404      → direct 模式（静态托管：GitHub Pages/Vercel，直连币安公开 API）
  网络失败           → direct 兜底
结果缓存，仅探测一次
```

### 各环境策略

| 环境 | 模式 | 说明 |
|---|---|---|
| 本机开发 | proxy | Vite `server.proxy`：`/api → data-api.binance.vision`、`/ws → stream.binance.com:443`、`/fapi` `/futures → fapi.binance.com`（`src/data/binance/endpoints.ts` 与 `vite.config.ts` 同一份域名表） |
| GitHub Pages / Vercel 静态托管 | direct | `buildApiUrl()` 按路径前缀拼 DIRECT_BASES：`/api→data-api.binance.vision`、`/fapi`/`/futures→fapi.binance.com`（该域名带 CORS）；直连 WS 用 `stream.binance.com:9443` |
| 受限网络 / 自建代理 | proxy | `/api` `/ws` `/fapi` `/futures` 相对路径由代理层转发，可加缓存与限流 |

### 多源降级（A15）

```
REST 主源不可达：
  fapi.binance.com（USDT-M）→ dapi.binance.com（COIN-M，同构端点，toCoinMSymbol/toCoinMPair 转换）
盘口/深度直连候选（spot → fstream → dstream）按序尝试
```

**说明**：与早期「前端禁止硬编码外部域」的设计不同，direct 模式下前端确实持有
`data-api.binance.vision` / `fapi.binance.com` / `dapi.binance.com` 三个白名单域名
（`endpoints.ts` 的 DIRECT_BASES）。代理部署与静态直连由 `detectMode()` 自动选择。

## 七、风险与对策

| 风险 | 影响 | 对策（按已落地实现） |
|---|---|---|
| 币安 API 网络不可达 | 数据源中断 | `detectMode()` proxy/direct 自动探测；直连模式 DIRECT_BASES 三域名 + **fapi→dapi COIN-M 兜底（A15）**；静态托管走直连、自建部署走代理 |
| 币安 API 协议变更 | 数据解析失效 | 数据层单一封装点（`data/binance/rest.ts` 映射集中处理），适配层隔离 |
| WS 断流丢 K 线 | 图表缺口 | 消息看门狗（10s 无消息判断流）+ 指数退避重连（上限 30s）+ 重连后 REST 回补（A3/A14）；仓库层幂等去重 |
| 大量 K 线内存/性能 | 卡顿 | 数据窗口裁剪（仅保留可视区 ± 缓冲）+ 实时帧 rAF 节流（A4）+ `?perf=N` 合成压测验证 |
| 冷启动慢 / 网络抖动 | 首屏等待 | K 线本地缓存（A13，6h TTL 失效自动降级）+ 图表错误态手动重试（E14）+ 离线提示条 |
| lightweight-charts 功能不足 | 被库约束 | adapter 隔离（`chart/adapter.ts` 单点封装），备选 klinecharts 可替换 |
| 指标计算开销 | 卡顿 | 指标纯函数 + 按窗口切片重算（`useMemo(windowData)`），参数面板即时生效 |
