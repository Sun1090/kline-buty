# 08 · 价格提醒与离盘纪律

> <mark>价格提醒</mark>（Price Alert）是行情工具里最便宜、也最被低估的纪律工具：设定一个价格条件，触发时由系统叫你回来。**它的本质不是「抓住行情」，而是把「条件→行动」的触发环节外包给系统，把你的注意力从屏幕前赎回来**——盯盘消耗的不只是时间，更是你在关键时刻做出正确决策的判断力。

::: tip 💡 一句话总纲
一句话总纲：**提醒代替盯盘，但不代替决策。** 提醒只负责把你叫回屏幕，行动依据永远回交易计划里找。
:::

---

## 1. 盯盘的代价

「盯盘 = 认真负责」是新手的直觉，实际发生的事情往往相反：

| 代价 | 机制 |
|---|---|
| 注意力消耗 | 高频浏览让大脑持续处理无意义波动，真正关键的信号反而被疲劳钝化 |
| 情绪化触发 | 每次刷新都是一次「诱惑」：价格没到条件位，也忍不住想「先动一动」 |
| 被迫接噪音 | 短周期盯盘看到的大多是随机波动，频繁暴露在高噪音下必然产生「做点什么」的冲动 |
| 仓位变相失控 | 盯着浮盈浮亏，情绪随数字起伏，容易提前止盈/恐慌止损，破坏计划 |

特别是一天盯 1m / 5m 图的习惯：你不是在「跟踪行情」，而是在**被迫接收最高比例的噪音**。看得越细，越容易把随机波动读成信号，越容易在计划之外动手。这与人性的弱点共振——[行为金融学](../behavioral-finance/)篇里讲的损失厌恶与近因效应，在盯盘场景会被成倍放大。

::: tip 💡 注意力是仓位的一部分
决策质量依赖注意力质量。把有限的注意力花在「计划执行的关键时点」，而不是「每一分钟的波动」上，本身就是一种风控。
:::

## 2. 提醒的正确角色：外包「条件→行动」，不外包决策

交易计划（见[交易计划](trading-plan.md)篇）把交易拆成可判断的条件：「价格到 X 就做 Y」。提醒做的事非常单纯：**系统替你守着条件，触发时把你叫回来**。

这里的关键边界：

- 提醒**代替盯盘**：你不需要用眼睛轮询市场，系统不会漏、不会累、不会手滑。
- 提醒**不代替决策**：触发提醒 ≠ 自动执行。「价格突破了提醒位」只说明条件之一满足，进不进、进多少、止损放哪，仍然回到计划。

用一句话区分：「提醒是闹钟，不是自动交易。」闹钟响起意味着「该回来处理这件事了」，而不是「该买入了」。

## 3. 提醒怎么设置才有效

### 3.1 绑定计划关键位，而不是整数关口

设置提醒最常见的错误是「凭感觉挂整数」：挂 30000、50000 这种心理关口。这类位置既不是你的入场条件，也不是你的止损依据，触发后你没有任何预案，等于**把噪音直接接进了通知栏**。

正确做法：每条提醒对应交易计划里的一个关键位——

| 提醒类型 | 绑定计划中的哪一项 | 触发后该做什么 |
|---|---|---|
| 突破确认位 | 入场规则里的「突破 X 且收盘确认」 | 回看计划：确认条件是否全部满足，满足才入场 |
| 止损预警位 | 止损规则的前一档缓冲位（如止损 −1%，预警 −0.7%） | 预演离场：检查是否需要按计划减仓/离场，不临时改止损 |
| 加仓触发位 | 仓位管理里的「回踩至 Y 附近加仓」 | 核对加仓前提（趋势未坏、总仓位未超限）再执行 |
| 结构位接近提醒 | 大周期支撑压力位前 0.5%~1% | 提前进入观察状态，等确认信号 |

这样设置后，**每一条提醒触发时你都有预案**——这是提醒与计划同源的直接好处。

### 3.2 用「条件提醒」而不是单一价格

主流平台多支持条件提醒（如「价格上穿」「跌幅超过 N%」「涨回均价上方」）。能写条件的，优先写条件，让提醒本身更贴近计划的措辞，减少触发后的「翻译成本」。

## 4. 提醒过载：太多提醒等于没有提醒

提醒机制的死穴是过载：触发太频繁 → 大脑将其归为背景噪音 → 真正关键的那一次被忽略。这与[多周期分析](../technical-analysis/multi-timeframe.md)里的「确认偏误」是同一种病：信息越多，越容易只听见自己想听的。

**上限建议**：

- 单品种同时生效的提醒 **≤ 5 条**；全部持仓合计 **≤ 10 条**。
- 每条提醒必须能回答两个问题：「它对应计划里的哪一条？」「触发后我做什么？」答不上来的，删。
- 定期（如每周检视时，见[交易日志与检视清单](journaling-checklists.md)）清理：与当前计划无关的提醒、纯整数关口提醒、上周触发过但没行动的提醒。

::: warning 🔄 与计划同源才保留
判断一条提醒该不该存在，唯一标准是「它是否来自当前交易计划」。计划之外挂的提醒，无论多「顺手」，都是在为冲动交易开后门。
:::

## 5. 触发之后怎么办：触发 ≠ 入场

提醒触发后的标准动作，是一个固定的三步流程：

```text
1. 停：不立刻下单。提醒只说明「价格条件满足」，不说明「交易成立」。
2. 查：回到交易计划，核对这一条触发对应的所有前提——
   方向允许吗？量能确认了吗？总仓位超限吗？今天是计划的执行日吗？
3. 行：全部满足 → 按计划执行（含止损与仓位）；
   任一不满足 → 记录「触发但放弃」，注明原因，结束。
```

「触发但放弃」的记录非常重要：它和成功的交易一样有价值——这是你分辨「提醒系统有效」和「条件设计有效」的证据。复盘时如果发现大量「触发即放弃」，说明提醒条件比计划松，需要收紧提醒定义。

反向的坑同样要警惕：**把提醒当信号源，触发就进**。这等于把计划里的入场条件压缩成单一价格条件，所有确认步骤在按下确认键的瞬间被跳过——提醒成了冲动交易的加速器，而不是纪律工具。

## 6. 桌面通知与声音的工具性使用

提醒的投递方式本身也影响纪律：

- **分级投递**：止损预警这类「必须立刻处理」的提醒用声音/强通知；结构位接近这类「进入观察即可」的用静默推送。全用强提醒 = 重新制造过载。
- **关闭行情类常驻推送**：行情软件的「大涨大跌」「成交播报」默认推送与你的计划无关，一律关闭——它们是噪音的入口。
- **触发后的仪式感**：强提醒触发后，走到屏幕前第一件事是打开交易计划页，而不是行情页。这个顺序本身就是纪律训练。

::: tip 💡 工具链小结
提醒系统（值守）+ 交易计划（决策依据）+ 交易日志（行为记录）构成闭环：提醒把你叫回来，计划告诉你做什么，日志记录你实际做了什么。
:::

::: warning ⚠️ 风险提示
价格提醒存在延迟与漏报可能，极端行情下价格可能瞬间击穿提醒位与止损位；提醒触发不构成交易信号，跳过计划核对直接执行极易造成亏损。任何提醒机制都不能替代止损单与仓位管理。
:::
