> 规范：已有实现必须审计并补足测试后才可标记完成；禁止跳过失败测试；禁止只改清单。

## 证据纪律（硬规则，不是感想——连续栽了三次之后写下来）

前三条是**同一种错**的三次实例：用一个比真实总体小的观测量去断言总体。
每一条都写成「怎么做」，不是「要谨慎」。

### 规则 1 · 观测量必须覆盖总体，否则只能证明局部

判词、计数、摘要**取的是哪一段**，必须写出来。取尾部若干条 ≠ 取整段。
- 错例：`viewWrites.slice(-6)` 的结果是「最后 6 条里没有 settle」，
  被读成「settle 从未执行」。落定广播发生在 `pointerup` 之后，
  之后每次可见区间事件都追加条目，把 `settle` 挤出窗口。
- 做法：数量类断言一律取**整段计数**（`summarizeViewWrites`），
  且长度只随 kind/sym 的**种类数**增长，不随事件条数增长（400 条与 4 条同长）。
- 自检：这句话如果末尾是「…里没有」，就把它改写成「整段里没有」再读一遍。

### 规则 2 · 「观测到 0」≠「路径没执行」，除非那个 0 在构造上不可能是别的原因

**0 必须能被解释**。`settle×0` 曾被读成「第二层惰性 / 死代码」，
而真相是**去重在正常工作**：`settle` 的设计就是「只在有差量时发」，
而 `report` 路径也写 `lastBroadcastRef`，手势途中那几帧已经把最终落点播出去了。
于是「末次 report 区间 == 落定读到的区间」这种设法下 `settle×0` 是**恒真的** ——
它**证不了死代码**。
- 做法：要证明某条路径活着，必须构造一个**它必然触发**的输入。
  本项目那条判据在 `src/components/__tests__/ChartView.settleBroadcast.test.tsx`：
  末次 report 之后把图表真实可见区间挪到别处，落定才有差量可说。
- 自检：写下「为什么这里是 0」，写不出来就是没测到，不是没发生。

### 规则 3 · 单次 run 不代表所有 run；本机绿 ≠ 没问题；CI 绿一次 ≠ 问题不存在

三次同形状：「#270 绿过一次 → 已修复」（被 #273 推翻）、
「只有 webkit 那一条红」（一次 run 的现象当范围界定）、
「本机 24/24 绿 → 范围已确认」。
- 做法：结论要标**证据形状**，至少给出一条：
  `git merge-base` 核实过 / 变异转红过 / 整段计数读出过。
  给不出形状的句子，删掉或标成猜测。
- 做法：**每个变异单独做**，不要把两个变异合成一个。
  合成只能证明「有东西变红」，不能区分是哪一处。

### 规则 4 · 门禁的量必须等于坏的入口的范围

R16.114 那次把归属判给了上游，门禁**只扫正文锚点、没扫目录**，
于是「绿」着把 270 条坏目录放上线。绿的范围 < 坏的范围 = 假绿。
- 做法：新加判据前先问「坏的东西有几种入口形状」，门禁要**逐个覆盖**。

### 规则 5 · 单测/工具链也分不出恒真判据 —— 靠**变异**分

写完判据先做两个方向的变异：去掉修复应转红、去掉保护应转红、加回应全绿。
本轮实证：`vitest` 与 `eslint` 都放过了一处**未使用的局部变量**
（变异残留 `const prev = ...`），只有 `npm run build` 的类型检查报出来
（`TS6133`）—— 与 progress 里已记的「`npm run build` 与 `tsc --noEmit` 不是同一道门」
是同一族：**每道门只覆盖自己那一类错，必须并集起来才算验过**。

### 规则 6 · 取证顺序：先取全量日志，再决定改哪里

「先改代码、最后才去看失败 run 的日志」是本项目已犯过的错。
另一条路走不通：`gh run view --job <id> --log` **只保留失败输出**，
不含被 gate 掉的 `console`，所以**取样窗口得先改**（#280 就是干这个的）。

### 规则 7 · 写「已做 X」之前先 `grep` 一次

2026-10-06 第四次同形状：「把意图写成已完成的动作」。
一句「纪律第四条：断言必须写清为什么这条必须是 0 或 ≥1……**已写进测试文件头**」，
`grep` 回去是 **0 命中**；而且**根本没有「第四条」**（纪律是规则 1–6，规则 4 是另一条）。
同批还有一句「#282 补上了 #222 第二层至今缺失的判据」，而 `:114` 在随后两个
**一行产品代码都没动**的 PR 上又红了两次 —— 话写完了，事情没发生。

- 做法：任何「已…」「已写进…」「已撤掉…」落笔前，对目标文件 `grep` 一次并把结果贴进 commit。
  写「撤掉某例外」还要贴该门在**最近若干次**检查上的实际结论（不能凭印象）。
- 判据：**一句话如果描述的是「我打算做」而不是「我 grep 到过」，它就还是猜测。**

### 规则 8 · 变异后必须 rebuild，否则「变异没被杀掉」是自欺

2026-10-06 栽在 E2E 上：改完 `ChartView.tsx` 就直接跑 `playwright test`，
变异版依然绿。我据此写下「这条新测试不可靠」，差点把一个真判据扔掉。
真相是 **`dist` 还是修复前的产物** —— 补一次 `npm run build` 再跑，
变异立刻被杀（`release(expired)` 0 → 1，`owned=false` 3~6 → 15~16）。

单测有 vitest 的源码直读，**没有这个问题**；只有「跑构建产物」的门才需要记得 rebuild。
- 做法：变异验证固定三步 —— 改源码 → **build** → 跑测试。少一步就等于没变异。
- 自检：变异跑绿时，先怀疑「我是不是忘了 build / 有没有残留 `dist`」，
  怀疑顺序是：产物是否陈旧 → 参数是否传错 → 判据是否恒真。**不要一上来就改判据。**

### 规则 9 · 「机器快慢」是会伪装成「本机绿 / CI 红」的根因，别只当玄学

同一个缺陷在本机永远绿、在 CI 永远红，最容易被记成「CI 环境玄学，本机过就行」。
本轮 #279 实测：根因是 `OWNED_MAX_MS=3s` 实为**手势时长上限**，
而 `panCell` 有 24 次串行 `await mouse.move` —— 本机 1.5s 内跑完所以碰不到，
CI 慢机上轻易超过 3s。
- 做法：判定「本机/CI 不一致」时，先**把那个环境差异量化成测试里的一个量**
  （#286 直接每步加 `waitForTimeout(150)`，让本机也慢过 3s），而不是记成玄学。
- 价值：这样这条判据才在**本机**具备变异可转红的能力，不必依赖 CI 才能证伪。

### 先量出真实失效面，再决定换不换（规则 3）

我第一版把旧口径的失效面写成「跨日界就废」，**那是错的**。本机穷举一整年 1460 组后订正：

| 窗口 | 真实跨度 | 旧口径 |
|---|---|---|
| `06/10 12:00 — 06/10 19:29` | 449 | 449 ✅ |
| `06/10 23:30 — 06/11 00:30` | 60 | 60 ✅ |
| `06/30 22:00 — 07/01 00:00` | 120 | **1560** ❌ |

`DD*31` 对 `DD` 单调 ⇒ 同月内跨任意天都精确；作废的只有 `DD` 回绕的跨月界。
**把失效面夸大成跨日界，会让下一个人以为跨日界已经修好、从而不管真正的跨月界。**

仍然换：判词依赖「窗口不跨月」这个**未被断言的隐含前提**（跨度约 449–480 分钟，
压住月末 12 天的概率 ≈ 0.09%）。频率低，但性质是规则 4「门禁量程 < 坏的入口」。
A11 条本来就带 `data-visible-from/to` 原始秒，换口径零成本。

### 换口径时被测试逼出来的两个真缺陷

1. **向上找 A11 条没有上界 → 捡到邻格的区间。** A11 条仅在 `visibleRange.from != null`
   时渲染；某格还没上报时「无上限往祖先找」会捡到同 grid 里**别的格**的区间，该格被判成
   Δ=0（完全同步）—— 规则 6 那类恒真判据。修法：走到含有别的 `quad-period-` 选择器的
   祖先就停，宁可报 `null`。
2. **「读不到区间」有两种，混成一种 = 把真缺陷静默降级成瞬态。** 没找到元素 = 该格还没
   上报（正常瞬态）；元素在但秒属性读不出来 = 属性被改名/没写（**接线坏了**）。现在拆成
   `ranges[sym] === null` 与 `missingAttr[]`，判词把后者提到最前面。

### 判据没有放松 + 变异证明（每个单独做，规则 3/8）

  4. 于是「末次 report 区间 == 落定读到的区间」这种设法下 `settle×0` 是**恒真的**，

  | 去掉去重判断 | 「无差量时必须去重」+ 既有 #222 第二层判据 |
  | 加回来 | 4/4 绿，既有 26 条 #222 用例一条不受影响 |
- **顺带钉住两处此前没被读数覆盖的真实行为**（这才是 #270 第二层存在的理由）：
  - 迁移后末次 report 换算出的时间是**退化单根**（`from=to=1786953480`，区间与 `base=2400`
    错位后被 clamp），而落定那一拍读到的是装载后的 `[0,100]`；
  - 两者**差量**存在，落定因此把真实落点播出去 —— 这条是第二层的全部价值。

## 2026-10-06 · #279 成因读出：`expired` = 归属超时，不是迁移夺权；顺带修好 #222 的兜底口径

### 判词直接说了成因（#283 那条「`release` 按成因分开数」的回报）

```
claim1/release1(expired×1) ⚠归属曾被超时兜底收回 settle×0
末位落点: BTC/ETH/SOL/BNB report owned=false
```

`claim×1 / release×1` **配平** → 归属链路是通的。`expired` 是**归属 3s 超时兜底**，
不是 cull 迁移夺权 —— **这一族与 #222 确实不同族**（#222 是迁移夺走归属）。
`owned=false` 只在被广播门挡下的那次上报里才记 → 锚格最后那一拍被挡下，兄弟格停在旧位置。

### 根因：代码和它自己的注释说的不是一回事

注释写「手势序列超 3s **无新事件** → 归属自动归还」= **空闲超时**；
但 `lastClaimAtRef` 只在 `pointerdown`（`ChartView.tsx:452`）写一次，拖动途中不再刷新
—— 于是 `OWNED_MAX_MS` 实际是**手势时长上限**。一次超过 3s 的正常慢拖动会被判成「手势已放弃」。

### 改法（#285）：顺延必须在过期判定**之前**

```ts
const userDriving = trusted && viewOwnedByUserRef.current
if (userDriving) lastClaimAtRef.current = now
if (viewOwnedByUserRef.current && now - lastClaimAtRef.current > OWNED_MAX_MS) { … }
```

**顺序不能反**：反过来写的话，超时那一帧会把计时器推回去、兜底永远不触发
—— 而那正是本条要修的 bug（原先根本没有顺延）。我第一版就写反了，被新判据当场抓住。

### 两条判据互为对照，两个变异各自只杀一条

| 判据 | 变异 | 结果 |
|---|---|---|
| 手势仍在进行时**不该**超时 | 去掉顺延 | 只有这条红 |
| 手势真正静止时**仍须**兜底 | 废掉兜底 | 只有这条红 |

第二条是 **#222 的地基**：webkit 的合成鼠标序列可能压根不派发 pointerup，
此时没有任何用户事件来顺延，归属必须仍自动归还、程序落位不许被当成用户意图广播。
**修「慢拖动被误判」不能顺手把「卡死手势不归还」也修掉** —— 两条必须同时成立。

它只是 `release` 的一种成因。测试夹具里我第一版断言 `counts.expired`，只按 kind 计数时
它会被算进普通 release，于是**恒绿** —— 这是规则 2 的又一次实例，形态是「判据写错被当成路径没跑」。

- 方法论（本批新增，都是可复用的判据而不是一次性结论）：
  1. **「负载 flake」要把预算当被测对象**，不要停在「机器忙」这句话上。三步：调低到能**精确复刻**那条红
     （1100ms 复现了 `Unable to find [data-testid="sentiment-panel"]`）⇒ 证明配方有效且因果在此；
     开到极大去**量**真实需求（整条测试极限负载下 4.6s）⇒ 拿到上界；再拿「永远不出现的钩子」当对照组
     证明真失败仍红且**报对判词**（8006ms 报的是 DOM dump 而不是 `Test timed out`）。中间那个数才是被测量出来的。
  2. **抬上限不改「等没发生」类断言的语义**：`waitFor` 在回调不抛异常时即刻 resolve，
     所以 `waitFor(() => expect(spy).not.toHaveBeenCalled())` 第一次轮询就过 —— 全仓只有这一类需要排查，排查过即可放心全局改。
  3. **squash 合并会把多提交正文留在 main 的提交信息里**：PR #206 的 body 因 `-F body=@<不存在的文件>`
     变成那串字面量本身（14 个字符，就是一行路径），但 `git log -1 3d4c0f2` 仍是完整取证记录。
     用文件传 body 之后要校验落库长度（`gh pr view --json body -q '.body|length'`），别默认它挂上了。
  4. **堆叠分支 + squash 合并 = 下一条必然带冲突，而且冲突只在 `merge-tree` 里看得见。**
     本轮一天之内踩两次（#213→#215、#214→#218）：B 分支基在 A 分支上，A 以 squash 进 main 之后，
     三方合并的 base 仍是 A 之前的那个提交，于是 A 的内容在 B 侧被当成「你这边的新增」重放一遍，
     `git merge-tree` 直接报 `CONFLICT (content)`，把 `<<<<<<<` 写进 `e2e/ci-specs.json`。
     判据不是「PR 页面显示可合并」，而是开合之前跑一次
     `git merge-tree --write-tree origin/main origin/<分支>` 看有没有 `CONFLICT` 行。
     禁 force-push 的前提下只有一条干净路：`git rebase --onto origin/main <A的tip> <分支>` 重落到
     **新分支名**、开新 PR、旧 PR 留一条指过去的判词再关闭 —— 变基途中 git 会把已进 main 的提交
     判为 `patch contents already upstream` 自动丢弃，这是正常的，不是丢了活。
  5. **一条断言「精简后红、逐字版绿」不等于找到了因果。** sentiment-live 拆出去时我删掉三条标题断言，
     `getByText(/%/)` 就等满 20s 不出现；原样不动 989ms 就过。听起来像「那三条是同步点」，
     但标题都是静态文本、三条 `toBeVisible` 合计不到一个毫秒，这个因果站不住；更硬的混淆项是
     我自己反复本地跑把 fapi 打到限流。所以文件头只记现象与「保持逐字」这个稳妥结论，
     不把猜测写成机制 —— 写错的机制比没写更贵。
  6. **「现扫坐标」必须配「按结果重试」，否则扫到的还是上一个刻度下的位置。** `?perf` 的价格轴会在
     蜡烛首次上屏之后约 **0.42s 再做一次离散重缩放**：画线质心一次性从 `y=422.3` 跳到 `y=449.9`
     （**27.6px**）然后才稳，3/3 复现。（这里原先还写着「线上 0/3 有跳变，是网络把测试推过了那个时刻」——
     那是把一次粗采样当成了机制，密采样重测见本条末尾。）于是「扫一次质心 → 照着它 tap/长按」在 perf 下会按在空白上：
     画线**创建**照常成功、localStorage 里两点俱在，只有随后的**编辑/长按**整条落空。
     移动端两条用例就是这么红的（一条四个增量全 0，一条 `mobile-text-editor` not found）。
     修法**不是**加大超时或加固定 sleep：一次性迟到的重缩放，睡多久都证明不了它已经过去；
     要按结果收敛 —— 没挪动／没打开就重扫当前像素再来一轮，并把「第几轮成的」写进判词。
     验证重试不是装饰，就把上限压成 1：整线拖动 8 跑红 6（判词 `{"used":1,"dP0":0,"dP1":0}`），
     恢复 3 轮后 8 跑全绿；长按文本不重试基线是 live 8/8、`?perf` 7/8，加重试后 `?perf` 16/16。
     同一条 `?perf` 契约也否掉了一个想法：`waitCandlesRendered` 只是「像素有了」的门，
     **不是**「图表落定了」的门，凡后面还要照像素做手势的都欠它一个收尾条件。
     **这条契约的时钟与边界，2026-09-24 用密采样重新量过**（本地 `main@8d220f9` 的 dist，chromium，
     一条固定价位的水平线放上屏那一刻记作 t=0，每 120ms 采一次质心、采 6s）：
     线上真实行情 **46 拍零跳变**（`y=362.5 → 364.5`，总变化 2px）；`?perf=600` 前 934ms 稳在 `332.5`，
     **t=+1078ms 一次性跳 15px 到 347.5**，此后 4.8s 再没动过。两个结论因此改掉：
     ① 线上不是「被网络推过了那个时刻」，而是**这条窗口里根本没有那次重缩放**；
     ② perf 的 pop 是**一次性、约 1s**（原来的 0.42s 是相对 `waitCandlesRendered` 的时钟，两者不矛盾，
     但没写参照点的「几秒」就是这次要改的毛病）。**成因仍未定** —— 只跳一次 ⇒ 不是每秒的合成 tick，
     没有插桩就不写成机制。产品口径按现状留着：主路径看不见它，`?perf` 压测模式会看见一次 pop，
     测试侧一律按结果收敛，不为此改产品代码。
