# 验收标准

## 自动门禁

按变更范围执行，不要只挑最轻的命令：

```bash
npm run typecheck
npm run lint
npm test
npm run build
npm run e2e
npm run perf      # 性能敏感路径
npm run audit:i18n # 文案变更
```

所有命令必须以最终工作区状态重新通过；不能拿改动前的旧结果交差。

## 手动浏览验收

### 主应用 PC

1. 启动 `npm run dev` 后打开 `http://localhost:5173/`。
2. 确认实时 WS 更新反映到最新价、最新 K 线和盘口，不需要手动刷新。
3. 切换至少三个周期和一个交易对，确认缓存、加载态、图表比例正常。
4. 打开主图 / 副图指标、深度、订单簿、持仓、提醒、回放、多图布局。
5. 创建、选中、拖动、删除至少一种画线，刷新后确认持久化。
6. 检查快捷键、搜索、主题、语言切换。

### 主应用移动端

1. DevTools 或真机设为 320px 与 390px。
2. `document.documentElement.scrollWidth === window.innerWidth`，无横向滚动。
3. 顶栏保持折叠；周期与关键功能换行直接可见。
4. 十字光标 OHLC 不溢出，底部贴近时向上翻转。
5. 双指缩放后双击可复位，垂直滑动不误滚页面。
6. 触屏创建 / 编辑 / 删除画线后自动回到只读模式。

### 知识库文档站

1. 运行 `npm run docs:build`，本地访问 `dist/knowledge/index.html` 对应静态服务。
2. 首页卡片、学习路线、角色导航在桌面和移动端均可读。
3. 侧栏每个篇章可展开，文章链接返回 200。
4. 点击带 `#` 的目录或跨章锚点，地址栏和滚动位置同时变化。
5. 直接粘贴深层 `.html#anchor` 地址打开，页面必须定位到标题。
6. 图片在浅色 / 深色主题下都不糊、不反白、不破图。

## 部署验收

1. Push 后等待 CI 通过，再等 GitHub Pages workflow 完成。
2. 抽查 Pages 应用与知识库 URL。
3. 有 Vercel 部署时也检查对应路径。
4. 对本次改动点做一次线上抽查，不只看构建日志。
5. 记录最终结论：通过、失败原因、回滚方式。
