# 05 · 部署指南

## 零配置：GitHub Pages / Vercel（静态托管）

**无需环境变量、无需服务器**。前端内置端点自动探测：

- 请求 `/api/v3/ping` 返回 JSON → 代理模式（走相对路径）
- 返回 HTML/404（静态托管的 SPA fallback）→ **直连币安公开 API**（其支持 CORS，浏览器可直接访问）

### 线上实例

| 平台 | 地址 | 构建参数 |
|---|---|---|
| GitHub Pages | https://sun1090.github.io/kline-buty/ | `VITE_BASE_PATH=/kline-buty/`（项目站点子路径） |
| Vercel | https://kline-buty.vercel.app/ | 默认根路径（不设 base） |

### GitHub Pages

仓库已包含 `.github/workflows/pages.yml`，推送到 `main` 自动构建部署。
只需在仓库 Settings → Pages → Source 选择 **GitHub Actions**（已配置）。

注意：Pages 项目站点部署在子路径 `/kline-buty/`，构建时通过
`VITE_BASE_PATH=/kline-buty/` 注入 Vite base；`vercel.json` 与 Docker 部署
不设置该变量（根路径）。

### Vercel

1. 在 Vercel 导入本仓库（自动识别 Vite，零配置）
2. 仓库内的 `vercel.json` 已配置 SPA rewrites
3. 直连模式下浏览器需能访问币安域名（国内网络可能受限，建议 Vercel 区域选海外）

### 知识库文档站（`/knowledge/` 子站点）

`npm run build` 会顺带构建 `docs-site/`（VitePress），产物合并进 `dist/knowledge/`，与应用一起静态托管：

| 平台 | 地址 | 说明 |
|---|---|---|
| GitHub Pages | https://sun1090.github.io/kline-buty/knowledge/ | CI 注入 `DOCS_BASE_PATH=/kline-buty/knowledge/` |
| Vercel | https://kline-buty.vercel.app/knowledge/ | 默认 base `/knowledge/`（不设该变量） |

- 章节链接采用 `.html` 直链（`cleanUrls:false`），任何静态托管直接命中，无需 URL 重写。
- 本地预览：`npm run docs:dev`（开发）或 `node scripts/serve-static.mjs <port>`（生产构建产物）。
- 应用内「更多 → 知识库」入口新标签打开子站。


- 依赖浏览器到币安的网络可达性（开发本机实测可达）
- 币安公开 API 有请求限流（按 IP），高频使用建议自建代理部署（见下）

## 一、Docker 部署（推荐，含代理）

```bash
docker build -t kline-buty .
docker run -d --name kline-buty -p 8080:80 kline-buty
# 访问 http://localhost:8080
```

nginx 已内置代理配置（`deploy/nginx.conf`）：
- `/api` → `data-api.binance.vision`（现货数据）
- `/ws` → `stream.binance.com`（WebSocket 实时流）
- `/fapi` → `fapi.binance.com`（永续/资金费率）

**无需修改前端代码**——前端只请求相对路径 `/api` `/ws` `/fapi` `/futures`（静态托管直连时 `/futures` 也拼 `fapi.binance.com`，因该域名带 CORS 而 `data-api.binance.vision` 的 `/futures/data` 不带，浏览器直连会被拦截）。

## 二、反向代理部署（已有 nginx）

将 `deploy/nginx.conf` 合并进你的站点配置，前端构建产物 `dist/` 指到对应 root 即可。

## 三、PWA / Service Worker 说明

- 生产构建自动包含 `sw.js`（离线缓存 + 后台提醒），仅 `PROD` 环境注册
- 后台提醒为**尽力而为**：浏览器会在空闲后终止 SW 定时器，无法保证页面关闭后持续提醒
  - 若要可靠后台推送：接入 Push API 需要推送服务器（VAPID keys），或使用 WebSocket 保活（VPS 常驻）
- HTTPS 是 PWA/通知的前置条件（localhost 除外）

## 四、国内服务器部署

币安域名在部分网络不可直连，nginx 代理同样会失败。对策：
1. 使用海外 VPS/容器平台（推荐，最简单）
2. 或在本机做一条 HTTPS 隧道（如 frp）把币安 API 转发到可直连的域名

## 五、环境要求

| 项 | 值 |
|---|---|
| Node（构建） | ≥ 22（jsdom 测试依赖 Node 22+ webidl API） |
| 运行时 | nginx 1.25+（Docker 镜像内置） |
| 客户端 | Chrome/Safari/Edge 最新两个大版本 |

## 六、冒烟清单（部署后）

1. 打开首页 → 状态栏显示「实时」
2. 切换周期/指标/交易对正常
3. 打开「深度」→ 深度曲线 100ms 刷新
4. 打开「仓位」→ 图上出现三条价格线、可拖拽
5. 打开「画线」→ 水平线/趋势线/斐波那契可创建、选中删除
6. 刷新页面 → 布局/指标参数/画线/提醒全部恢复（localStorage）
7. `curl https://你的域名/api/v3/klines?symbol=BTCUSDT&interval=1m&limit=2` 返回 JSON

### 2. 上线内容抽查（每平台两条，curl 特征抓取）

应用首页与知识库各一条，不只验 200，还要 grep 本次改动的特征（新容器类名 / frontmatter title / 图引用）：

```bash
# GitHub Pages（应用 + 知识库）
curl -s https://sun1090.github.io/kline-buty/ | grep -o "<title>[^<]*</title>"
curl -s https://sun1090.github.io/kline-buty/knowledge/ | grep -o "index\|404" | head -1

# Vercel（应用 + 知识库）
curl -s https://kline-buty.vercel.app/ | grep -o "<title>[^<]*</title>"
curl -s https://kline-buty.vercel.app/knowledge/ | grep -o "index\|404" | head -1
```

应用侧特征断言（版本历史面世后）：

```bash
curl -s https://sun1090.github.io/kline-buty/index.html | grep -c "kline-buty"
```

### 3. Docker 部署健康检查

```bash
docker build -t kline-buty .          # 构建须全绿（npm ci + tsc + vite + docs:build）
docker run -d --name kline-buty -p 8080:80 kline-buty
curl -sf -o /dev/null http://localhost:8080/                 # 首页 200
curl -sf -o /dev/null http://localhost:8080/anything/nested  # SPA fallback 200
curl -sf -o /dev/null http://localhost:8080/knowledge/       # 知识库子站 200
```

2026-09 实测：镜像构建曾因两处环境差异失败，已修复（见 CHANGELOG / Dockerfile 注释）：

- `npm ci` 缺 `.npmrc`（`legacy-peer-deps`）→ 严格 peer 解析 react@18 树 EUSAGE
- `node:22-alpine` 缺 `git` → vitepress lastUpdated `spawn git ENOENT`

镜像内 nginx 已代理 `/api` `/ws` `/fapi`（币安），容器内可验证：

```bash
docker exec kline-buty curl -sf https://data-api.binance.vision/api/v3/ping  # 网络可达性示意
```
